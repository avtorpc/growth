# Журнал решений

## Этап 1 — окружение и каркас

### Запуск

Требуются Docker Engine / Docker Desktop и Docker Compose v2. Локальные PHP, Composer,
Node.js и MySQL не нужны. Первый запуск требует доступа к реестрам образов и пакетов.
Все команды выполняются из корня репозитория:

```sh
cp docker/.env.example docker/.env
docker compose -f docker/compose.yaml up -d --build --wait
```

Открыть http://localhost:8080. Страница проверяет API и подключение к базе.
Проверка API: `curl -fsS http://localhost:8080/api/health`.
Ожидаемый ответ: `{"status":"ok","database":"ok"}`.

```sh
# Состояние и логи
docker compose -f docker/compose.yaml ps
docker compose -f docker/compose.yaml logs --tail=100
# Сборка Angular
docker compose -f docker/compose.yaml exec frontend npm run build
# Проверка контейнера Symfony
docker compose -f docker/compose.yaml exec backend php bin/console lint:container
# Остановка с сохранением данных
docker compose -f docker/compose.yaml down
```

Порт можно изменить через `APP_PORT` в `docker/.env`. Данные MySQL сохраняются в
именованном томе. Не добавляйте `-v` к `down`, если данные нужны.
Пароли из примера предназначены только для локальной разработки. При смене паролей
после первого запуска существующая база автоматически их не обновляет.

### Архитектура

- `backend/` — монолит Symfony: одно приложение, единая точка входа и база.
- `frontend/` — Angular, standalone-компонент и signals для состояния страницы.
- `docker/` — вся Docker-инфраструктура: Compose, Dockerfile, конфигурация Nginx,
  примеры переменных окружения и исключения контекста сборки.
- Четыре контейнера: Nginx, PHP-FPM, Angular dev server и MySQL 8.0.
  MySQL выбрана по обязательному условию задания; PostgreSQL не используется.
- Nginx публикует только один локальный порт. `/api/` идёт в Symfony, остальные
  запросы — в Angular. Общий origin избавляет от необходимости настраивать CORS.
- PHP 8.3 и Symfony 7.4 LTS. Composer подбирает зависимости с учётом PHP 8.3;
  версии пакетов сохранены в `composer.lock`.
- Angular 21 и Node 22 совместимы; версии пакетов сохранены в `package-lock.json`.
  Основание: https://angular.dev/reference/versions и https://symfony.com/releases/7.4.
- Образы закреплены по веткам, не по digest: обновления образов возможны при повторной
  загрузке. Для тестового окружения это допустимо; полностью воспроизводимые образы
  потребуют фиксации digest.
- Исходники подключены в контейнеры для разработки. После изменения зависимостей
  нужна повторная сборка. База не публикует порт на хосте.
- `/api/health` выполняет `SELECT 1` через PDO. При недоступности базы возвращает
  HTTP 503 без внутренних подробностей. Соединение получается лениво внутри try/catch.
  Выбор ORM и модель заказов остаются за следующим этапом.

### Границы этапа

Импорт, тарифы, таблицы заказов и фильтрация пока не реализованы. Тесты бизнес-логики
появятся вместе с ней. Сейчас проверяется реальная сборка и взаимодействие сервисов.
Авторизация, CI, очереди, деплой и production-сборка окружения не входят в этот этап.
На странице пока только проверка подключения, а не интерфейс импорта.

Исходное задание сохранено в README.MD без изменения текста. В приложенном JSON
есть переносы внутри ключей и значений: перед созданием фикстуры их нужно убрать,
сохранив намеренно некорректные бизнес-данные.

### AI и время

AI использован для создания каркаса, конфигураций и проверки запуска. Во время
проверки исправлен подбор транзитивных Symfony-пакетов: без `config.platform.php`
Composer выбирал зависимости для более новой PHP, чем в контейнере приложения.
Время и фактические результаты проверок записаны ниже по окончании этапа.

### Результаты проверки (10 октября 2026)

- Первичная сборка образов и запуск на новом томе MySQL выполнены успешно.
- Angular `npm run build` — успешно.
- Symfony `lint:container` и Composer `validate --strict` — успешно.
- `GET /api/health` через Nginx — HTTP 200, база доступна.
- Страница открыта в браузере: Angular показывает успешное подключение.
- При остановке MySQL API возвращает HTTP 503 и `database: unavailable`.
- Исправлен обнаруженный конфликт владельцев кэша: образ PHP запускается от
  `www-data`, поэтому консоль и PHP-FPM создают файлы от одного пользователя.
- Примерно 15 минут на этап: около 4 минут на каркас и документацию,
  7 минут на зависимости, загрузку образов и сборку, 4 минуты на проверки и исправления.
  Это время текущей сессии AI, включая ожидание сборок; время ручного изучения кода
  пользователем сюда не входит.
